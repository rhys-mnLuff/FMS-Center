This section is for whoever installs or services the sensor units — raw readings, calibration status and the live radio packet feed, matching Base_code / Sensor_code / CALIBRATION.md in the project repo.
Known simplifications in this demo (so this doesn't get mistaken for exactly-as-shipped behavior):
  • Alert state (Safe/Watch/Flood Risk): uses debounce + hysteresis, matching the design described in CALIBRATION.md for moisture_alert_logic.ino — but that logic is soil-only and, per the doc, "not yet wired to SMS." The shipped base_station.ino actually fires instantly on the first threshold-crossing reading, for both soil and water, no debounce. This demo extends the proposed soil design to water too, since neither is calibrated yet.
  • Reset thresholds (soil 500, water uses the same 200 as its alert point since no water hysteresis is documented anywhere) are demo placeholders — CALIBRATION.md explicitly calls its own TRIGGER_PCT/RESET_PCT "placeholder values, not derived numbers" pending calibration. Same status here.
  • SMS cooldown: the real firmware's 1-hour cooldown is a single global timer shared across all nodes (lastSmsTime in Base_code isn't per-node) — meaning one field's alert can suppress another field's real alert for up to an hour. This demo now models that faithfully (see the cooldown notice below when it's active), compressed to simulated time so you can actually see it happen.
  • Water sensor direction is unverified. Base_code's own comment: "WATER_ALERT_THRESHOLD direction NOT changed... Verify direction before trusting it." This demo uses the code's current (unverified) direction — higher raw value = more water.
  • "Relayed via" a specific node is illustrative, not literal. The real mesh (Sensor_code) is undirected flood-broadcast — any node in range bounces any packet it hears — with no hop-count or path field in the wire protocol, so the base station has no way to know a packet was relayed, let alone by whom.
  • Console RX/cloud lines below match the real packet format (<node,soil,water>) and query string exactly, but base_station.ino doesn't currently print received packets to Serial at all — only sensor_node.ino prints "Transmitted:"/"Bounced:" lines. The RX-side log format here is invented for readability.
